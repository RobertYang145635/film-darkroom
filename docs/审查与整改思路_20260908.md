## 一、缺陷不是随机分布的：六类反复复发的根因

按"这类 bug 还会再长出来"排序，不是按严重度。

| 类 | 表现（本轮实例） | 反制手段 |
|---|---|---|
| **A. 静默吞掉** | 损坏标注被 `except Exception: return None` 当成"没标定过"→ 覆盖用户基线；`--params` 解析完没传下去；"全部重置"按钮 emit 出去没人接 | 失败必须**留痕 + 可见 + 不可覆盖**；哑信号要么连要么删 |
| **B. 表示敏感** | 内容指纹对 int/float/numpy 标量敏感（同一几何实测 3 个指纹）；`to_dict()` 遇 np.int64 直接 TypeError；`.gitignore` UTF-8/GBK 混码 | 任何参与比较/哈希的值先**归一化**；哈希只覆盖语义字段 |
| **C. 跨对象串数据** | 防抖定时器把上一帧血缘写进新帧草稿；`_state_notice` 跨帧残留；画布像素与 `self.current` 不同源时拾点会写错帧 | 一切窗口级状态**随帧显式重置**；给数据打归属标记 |
| **D. 单一事实源缺失** | 同一 sRGB 公式 3 份、ROI 校验 2 份、仓库根反推 11 处、原子写 3 个版本 | 收敛到唯一实现（storage / color.management / io.atomic） |
| **E. 线程边界** | 分钟级整卷导出跑在 GUI 线程；worker 里建 QMessageBox、改 QListWidget item | `workers.py` 的契约要有门禁保障：**worker 只算不碰控件、不落盘** |
| **F. 声称 ≠ 实现** | `workflow.py` docstring 写"三入口共用"实际零引用；CHANGELOG 写"取消帧不再静默消失"但弹窗没报 cancelled；注释"场景坐标零换算"是错的 | 每次改数据层，**必须同时核对表现层**；注释带日期与可复现证据 |

**方法论结论**（这轮最值钱的产出）：
- 静态扫描（ruff）抓到 **A 类的 `--params`** 和一批卫生债，但把 `_patch_median` 定成致命却**没查调用图**，误判了用户可见性；
- 运行时探针 + 数据流追踪抓到 **E/C/F**（导出假死、串帧、指纹不稳定），但**完全漏了 `cli.py`**（没读那个文件）；
- 两者**都不够**：我把两份结论合并交叉验证后，才出现"推翻 3 条审计论断 + 补 2 条它们都没提的雷"。
- **测试全绿不是结论**：本轮实测两次——① 409 全绿的同时 `_patch_median` 贴边必崩（测试从没测"合法但近边缘"）；② 我合并 sRGB 三份实现时漏了模块级导入，**409 全绿而 ruff F821 立刻报**——证明 8 位 JPEG 编码路径在 pytest 里没有真实覆盖。

## 三、还欠什么，以及为什么是这个顺序

| 序 | 事项 | 为什么排这里 |
|---|---|---|
| 1 | **清 5 处反向依赖**（`io/sidecar→pipeline`×2、`quality_gate→pipeline.density`、`rollcalib→pipeline.backends`、`profiles→pipeline.params`） | 它是 D/E 类的地基：常量下沉 + 值注入做完，模块边界自然显形，下一步拆分才不是硬切 |

## 四、审核协议（本轮之后固定这么跑）

1. **改动即测**：每个可验证单元跑全量，红就整类回滚（ratchet 脚本已验证这套闸门有效）。
2. **反复审核**：同一批改动至少过两遍——一遍看 diff（找改动本身的问题），一遍不看 diff 读函数（找改动与上下文的断裂）。
3. **冷读审查**：由**没有上下文的新读者**执行，明确禁止读审查报告与作者理由。理由：本轮 3 条审计论断被证据推翻，全部来自"相信了上一层结论"。
4. **署名决定**：任何"看起来没人用所以留着"的东西（如 `batch_panel`）必须在代码里写下决定与待办，而不是靠 spec 里一行没人读的 hiddenimport。

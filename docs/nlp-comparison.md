# 与 Negative Lab Pro 对照（1298_G200 卷）

> **结论先行：全图 ΔE2000 对 NLP 不是有效的色彩验收指标。** 本节数字只用于
> 粗筛异常，不代表色彩准确度。真正的验收指标（§8.4 中性区 ΔE2000 ≤ 5）
> 需要**对齐后的中性色卡区域**，由 GUI 人工取点后再评。

## 为什么全图 ΔE 不可信

对照双方差异远超色彩本身：

1. **裁切区域不同**：本软件导出帧检测区域（含片基条带与片边），
   NLP 导出为其自动裁切（实测 4656×4723，接近方形）；
2. **构图/旋转不同**：翻拍原图竖向，NLP 可能已旋转；脚本尝试 4 方向取
   ΔE 最小，但选出的 rot 逐张乱跳（0/90/180/270），说明它在拟合亮度统计
   而非真实对齐——这本身就证明像素级对齐不成立；
3. **输出风格不同**：NLP 默认带自己的对比/饱和曲线（更暗更饱和），
   亮度差 lumΔ 从 −0.01 到 +0.34 不等。

因此 mean ΔE 15–37 主要由**构图错位 + 风格曲线**贡献，不能解读为"色偏 15–37"。

## 有效的下一步（Phase 3 验收真正需要的）

- 用户提供**含中性色卡/灰卡的样片**，或在本软件 GUI 中对同一帧人工取亮/暗中性点；
- 对齐到同一画面区域后，仅在中性区计算 ΔE2000（`diagnostics.colorimetry` 已就绪，
  `neutral_delta_e` 支持掩码）；
- 与 NLP 并排主观比较时，记录差异**原因**（高光/肤色/中性灰/阴影），
  而非只写"更好/更差"（§8.4 主观指标要求）。

# 开源去色罩「打印端点」调研（2026-10-07）

> 起因：`docs/blockers.md` B-11 实测到一次性自动出片系统性欠校正，根因是
> `pipeline/params.py:18` 把密度跨度写成常数 `dmax = 2.0`，而扣掉橙色片基后
> **画面内容只占 0.4–1.0 decade**（`G200-5` 仅 0.37）。
> 本文记录**外部实现到底怎么定这个跨度**，避免闭门造车。
> 调研方式：`gh api` 直接读源码（不是读 README 宣传语），三路并行。
> 本文所有数字都是**当日实测/当日读到的原文**，不是"当前状态"。

## 一、结论：没有一家把密度跨度写成常数

| 项目 | 许可 | 黑/白端点从哪来 | 有没有"等效打印曝光" | 卷级一致 |
| --- | --- | --- | --- | --- |

## 二、对我们最关键的三条

### 1. 跨度必须由**这一卷自己的密度分布**解出，且要有物性地板
negaflow 的改动说明就是冲这个问题去的（原文："고정 dmax 가 만든 압축을 제거"
= **移除固定 dmax 造成的压缩**），它同时给了物性下限 `1.8D` 与地板 `0.10`，
避免"端点跟着内容漂"。NegPy 的 `k = 2.9·range/(R/100)` 里
`range = 0.85·r·min((1−0.4)+0.4·(0.9/t), 1.2·(0.9/t))`，
其中 `r` 是实测亮度密度跨度、`t` 是**纹理跨度**（P10–P90），
`0.9` 是"正常负片纹理跨度"的名义值 ⇒ **跨度小就自动加硬把纸级铺满**，
这正是我们缺的那一环。

### 2. 端点与"打印曝光"是**两件正交的事**，必须分开
horizon 的注释说得最直白：`ENDPOINTS PLACE BLACK AND WHITE. THEY DO NOT PLACE MID-GREY.`
中灰由 **LATD→aim(0.18)** 那个闭式标量负责。filmeon 也是同一规则（几何平均亮度→0.18）。
我们只有 `dmax/offset` 一个旋钮，等于把两件事混在一个参数里——
所以"调跨度"与"调明暗"会互相打架。

### 3. 改端点**必须三通道共用（luma 域）**，否则颜色会跟着漂
horizon 记录了**失败实验**（`DEV-DRANGE`，把端点放宽到 p0.001/p99.999，已构建后删除）：
> it moved COLOUR. Midtone R-G shifted up to -14.4 codes …
> changing the endpoints while a NON-LINEAR exposure gamma sits downstream changes channel ratios

并且它的肩/趾关闭实验把越界从基线 2.35% 推到 2.57%（**更差**）。
⇒ 我们若把端点改成**逐通道**百分位，等于引入一个未验证的色偏源；
NegPy 的 `use_luma/color/cast_average` **默认 False** 也是同一谨慎。

## 三、片基之外的经验数字（可直接对照我们的测量）

- horizon 实测 **rebate→画面** 密度差：卷 A `+0.608` med、卷 B `+0.334` med
  ⇒ 与我们的"画面内密度只占 0.4–1.0 decade"**同一量级**，
  印证"以片基为黑点"对翻拍不成立。
- horizon 还记录尾部分布**不对称**：下尾 p0.02→p1 只占 4.9%/3.6%，
  上尾 p99→p99.98 占 43.9%/18.1% ⇒ **片基是硬底，高光没有底**。
- `color-neg-resources`（MIT）明确警告：
  > Don't use the burned film tip and transparent film base as these sit
  > outside the usable dynamic range of the film.
- 相纸端点是**发布常数**（不是胶片常数）：NegPy `d_max=2.3 / d_min=0.06`、
  horizon `dMin=0.060 / dMax=(2.66,2.53,2.48)`、Endura 实测 `2.556 / 0.095`。
  ⇒ 我们该引入的是"**纸级**常数 + **实测跨度**"两个量，而不是一个 2.0。

## 四、相机翻拍（我们的输入形态）的共有做法

| 事项 | 外部实现 |
| --- | --- |
| 光照不均 | `simple-inversion` `scan = log10(flat/scan)` 平场除法；DarkSlide `flatField.ts`（空光源参考帧→网格→离群局部平面拟合→除法，**相机不匹配就拒绝**）；negaflow `compute_gain = mean(blur)/blur`，clamp [0.25,4] |
| 片边/齿孔 | DarkSlide `frameDetection.ts` + `rollCropStabilization`（簇内**中位宽高**）；negaflow 齿孔槽位检测 + 内缩 6% 去黑框；film-convert `ignore_margin=0.03` |
| 方向 | DarkSlide 读 EXIF orientation + mirror；NegPy Auto Skew（高斯-牛顿） |
| 削顶报警 | NegPy `scan_clip ≥ 0.99` 报警（>1% 削顶）；`adjust_maximum_thr=0.0` 全卷统一解码标度 |
| 取样区 | NegPy 先 1024 格**块中值预滤**再取百分位；DarkSlide `sampleStats` 内缩 6% |

## 五、许可证边界（本项目 B-3 许可证仍未决，所以这条必须写死）

- **不可搬运任何代码/数据/注释**：`NegPy`（GPL-3.0，含 `*.wgsl`、
  `EXPOSURE_CONSTANTS`、`crosstalk/*.toml`）、`film-convert`（GPL-3.0）。
  另 `filmeon` 许可写明"不得修改、**逆向**、解密、再分发、创作衍生作品"
  ⇒ 只可用其**已公开的常数与概念**（Cineon 反 log、0.18 aim），
  其 GLSL/JS 与加密 `.dctle` 一律不碰。
- **可搬运但须保留版权声明**：MIT（horizon-film-lab、simple-inversion、
  DarkSlide、Signynt、color-negative-inversion）；Apache-2.0（negaflow，
  另含 NOTICE/TRADEMARKS 须保留）。
- **只取思路与数学结构**（对所有项目都安全）：百分位端点、luma 共用端点、
  LATD→aim、卷级池化 + 离群拒绝、纸级常数与物性地板分列。
- 具体常数值（`2.9 / 0.85 / 0.9 / 1.9 / 0.46 / 0.12` 这类组合）
  属各项目的**表达选择**，我们必须**自己标定**再写进来，不能照抄。

## 六、明确不采纳的路线（连同理由）

1. **引导片/平场帧方案**（`simple-inversion`）：数学最干净，但要求用户
   多拍一张引导片、且"扫描期间不得改相机与光源"——与 v5 §0.3
   "不需要色卡、不增加普通用户操作"的产品范围冲突。**不采纳为默认**，
   可作为研发/标定路径的备选。
2. **Trichrome 三张窄带曝光**（`TriRGB`、`digital-fauxice`）：需要改动采集工装，
   超出软件范围。
3. **人工两点取色**（`color-negative-inversion`）：与"一次性"目标相反。
4. **不做卷级色调一致**（horizon 的立场）：与我们的验收判据
   "同卷结果稳定得像同一次冲洗"直接冲突，**不采纳**。

## 七、这份调研落到代码上的问题（尚未实现）

我们缺的不是"更好的曲线"，而是两个此前混在一起的量：

- **跨度**：由**画面内**密度分布解出（luma 共用），带物性地板，卷级池化 + 离群拒绝；
- **打印曝光**：一个正交标量，把大面积透射密度/几何平均亮度钉到纸级 aim。

原型实验与结果见 `docs/blockers.md` B-11 追加（同日）。

## 0. 一页结论

1. **单点中性救援已经可用并已接入 UI**：在 (temp,tint) 控件族内直接数值
   求解（不是把拾点对角增益投影过去——那条路会衰减 78% 的修正）。可信
   拾点上端到端残差极差 0.494 → **0.001**（G200-1，注入蓝偏 0.10）。
   调整阶段右栏「色罩校正 → 中性点救援」→ 画布点一下 → 即时生效 +
   「撤销拾点」。
2. **拾点可信度可以被检测并已做成一级提示**：所需对角增益 >3x 时警告
   "该点可能不是中性场景点"（G200-4 演示固定点落在 R 通道极暗区域，
   救援只能部分收敛 0.712→0.414）；剪裁通道（≥0.98/≤0.02）单独警告
   信息丢失。两类警告进右栏 `lbl_pick_hint`（常驻）+ banner。
3. **全图 ΔE2000 不能当卷一致性指标**：三卷实测 mean 21.8/30.0/34.9、
   "离群帧"50-90%——场景内容差异完全主导（与 docs/nlp-comparison.md 的
   结论互证）。
4. **场景无关的正确锚点是片基色度**：1298 卷实测极差 0.014 decade
   （物理上极一致）、CN400 抓到 0.084 decade 的真实 B 通道漂移 +
   CN400-12 离群帧；1299 卷 9/11 帧退 generic_prior 本身就是一致性风险
   信号。generic_prior 帧混入统计会伪造漂移（0.176→0.084 的教训），
   口径必须只算实测片基帧。
5. **R5 精确求解**：增量叠加 M(delta)·M(base) ≈ M(base+delta) 只在
   "当前 intent 仅色温/色调"时成立；含影调/彩度控件时改为对技术正片
   补丁用完整 apply_render 逐点渲染求解绝对 temp/tint——base 故意偏冷
   (-40/-30) 也能一次吸收（残差极差 <0.05）。

## 1. R2 单点中性救援（先讲能用的）

### 1.1 为什么不是"增益投影"

用户拾取"这里应该是灰"的点后，物理量是一个线性域对角增益
`g_c = gray / point_c`。直觉做法是把它丢给 `candidates.gain_to_temp_tint`
反解色温/色调——**这条路线是错的**：

```text
注入蓝偏 (0,0,0.12) 的合成图，拾点要求增益 (1.24, 1.01, 0.80)：
gain_to_temp_tint 投影 -> temp=+6.6, tint=+10.6
施加后拾点极差 0.183 -> 0.142（只消 22%）
```

原因：(temperature, tint) 对应的 Bradford 适应矩阵在 RGB 域是非对角 3x3，
把 RGB 对角增益当"颜色"投影到日光轨迹+ tint 线上，两个自由度都失真。

### 1.2 正确解法：族内精确求解

在 (temp,tint) 控件族内**直接数值求解**：
`min_{temp,tint} spread( adaptation_matrix(temp,tint) @ 拾点中位 )`，
粗到细三轮 2D 网格（41×41 步长 5 → 11×11 步长 1 → 9×9 步长 0.2），
单次 <10ms。这是该二参数族内**可达的精确解**。

真实样片端到端（默认管线技术正片 + 注入色偏模拟自动翻车）：

| 样片 | 注入色偏 | 拾点极差 前→后 | 说明 |
|---|---|---|---|
| G200-1 | 蓝 (0,0,+0.10) | 0.494 → **0.001** | 可信拾点，完全中和 |
| G200-1 | 暖 (+0.08,+0.02,-0.06) | 0.267 → **0.015** | 完全中和 |
| G200-4 | 蓝 (0,0,+0.10) | 0.712 → 0.414 | 拾点 R:G:B=0.05:0.48:0.76（深色场景），非可信中性点 |

### 1.3 拾点可信度（新发现）

救援的物理上限由拾点本身决定：所需对角增益 `gray/point_c` 在真实
"该是灰"的点上通常 ≤2-3 倍；G200-4 的演示点需要 15 倍（R 通道极暗），
任何 (temp,tint) 都无法中和。已实现为警告：
`所需对角增益 >3.0x → "该点可能不是中性场景点，救援只能部分收敛"`。
对 UI 的含义：**取色器必须把这个警告做成一级提示**（NLP 的取色器正因为
不解释失败而口碑差）。

### 1.4 与现有链路的关系（不重复造轮子）

- `auto.py` 的 z 域中性参考（estimate_exponent_ratios / estimate_wb_high /
  estimate_wb_low）：作用于**负片技术参数**（InvertParams），需要负片上
  的亮/暗两点，是"技术底座标定"；`service.process_image` 已有
  `neutral_bright_points/neutral_dark_points` 入口。
- 本模块 `pipeline/rescue.py`：作用于**渲染后正片**，输出 RenderIntent，
  是"用户可见结果的即时救援"。施加路径 = 同一个 `apply_render`，
  与滑杆/候选共用数学，无第二套公式。
- 二者互补：底座标定解决"片基色度没除干净"，救援解决"剩一点的偏 +
  用户的主观意图"。

### 1.5 组合语义与边界

- 增量可直接叠加到当前 temp/tint 控件：适应矩阵在 LMS 域为对角乘积，
  `M(delta)·M(base) ≈ M(base+delta)`（当前 intent 只有色温/色调时精确；
  有影调/彩度控件时近似成立，误差后续量化）。
- 修不了的情况（如实）：拾点被剪裁（通道=1.0）后信息丢失；拾点非中性
  （上面的可信度警告）；单点只能定对角增益/二参数适应，**不能**修染料
  串扰（那需要 3x3 矩阵 + 多方向样本，见 docs/algorithm-notes.md §2.3
  可辨识性）。

## 2. R1/R3 卷一致性度量（度量先行）

### 2.1 度量设计（`diagnostics/consistency.py`）

- `frame_consistency(a, b, mask)`：两帧渲染正片在掩码内的 Lab ΔE2000
  统计 + **a*/b* 偏移向量与 L* 偏移分开报告**（色偏一致性与明暗差是
  两回事；蓝偏 = db* < 0）。
- `roll_consistency(frames)`：两两 ΔE 矩阵（对称、对角 0）+ 卷中位色偏
  + 每帧到卷中位的色偏距离（离群分）。
- 18 项测试锁定（含噪声地板：独立噪声 σ=0.003 时 ΔE≈0.7-1 是下限）。

### 2.2 真实样卷第一批数字（默认管线，自动 ROI，输出裁切内）

| 卷 | 帧数 | ΔE mean | ΔE p50 | ΔE p95 | "离群"帧 |
|---|---|---|---|---|---|
| 1298_G200 | 12 | 21.8 | 20.3 | 37.0 | 7/12 |
| 1299_G200 | 11 | 30.0 | 30.2 | 46.6 | 10/11 |
| 1300_CN400 | 12 | 34.9 | 34.0 | 49.6 | 6/12 |

### 2.3 关键发现：全图 ΔE 被场景主导（负面结果，如实报告）

1299 卷 10/11 帧被判"离群"——这不是处理漂移，是**不同场景的内容差异**
（山景/天空/水面本来就是不同颜色）。这与 docs/nlp-comparison.md 的结论
（"全图 ΔE2000 对 NLP 不是有效的色彩验收指标"）在同一份数据上再次成立。
**推论：卷一致性必须用场景无关的锚点来量。**

候选锚点（按可行性排序）：

1. **片基色度**（本轮已落地采集）：同一卷同一次冲洗，未曝光片基的
   log10 通道比应恒定。它是纯"处理一致性"信号——dmin 解析、卷级共享、
   wb_high 全部体现在这里。逐帧片基 Dmin 色度散布已加入基线 JSON
   （`base_chroma` 字段），重跑后的散布数字见 §2.4。
2. **同场景帧对**：用户在基准集里标注"这两张拍的是同一场景"后，
   帧对 ΔE 才有处理语义——依赖人工判定基准集（痛点调研 P0-1）。
3. **中性参考物**：灰卡/已知中性物入镜——改变拍摄流程，不作为默认。

### 2.4 片基色度散布（场景无关锚点，三卷实测）

口径修正（过程中的真发现）：初版把 generic_prior 帧混进散布统计，CN400
因此显示 0.176 decade 漂移——**那是通用先验资产常量的形状（3 帧），不是
该片基的漂移**。修正为只统计实测片基帧后数字如下：

| 卷 | 实测片基帧数 | 排除 prior 帧 | max_abs_drift (decade) | 逐通道 std |
|---|---|---|---|---|
| 1298_G200 | 11 | 1 | **0.014** | [0.0007, 0.0012, 0.0043] |
| 1299_G200 | 2 | 9 | 0.010（仅 2 帧，统计力弱） | [0.0011, 0.0013, 0.0049] |
| 1300_CN400 | 9 | 3 | **0.084** | [0.0014, 0.0056, 0.0243] |

解读：
- **1298 卷片基色度极一致**（0.014 decade ≈ 3.3% 透射率差）——这一卷的
  "处理一致性"在物理上是好的；全图 ΔE 21.8 全部来自场景内容。
- **CN400 抓到一个真实信号**：B 通道 -0.73~-0.82（std 0.024），离群帧
  CN400-12（-0.7315；**2026-09-08 复核更正**：按提交数据 9 帧实测中位是
  -0.7943，偏离 **+0.0628 decade ≈ 15.6%**，原文写 +0.036/8.7% 与数据不符；
  极差 0.0838 与 max_abs_drift 一致，结论方向不变）。这是片基取样区/
  背光微漂移的痕迹，正是该度量应该抓的东西；1299 卷 9/11 帧退到
  generic_prior（片基置信度普遍 0.05-0.11）本身就是"这卷片基取样薄弱"
  的一致性证据，比任何全图 ΔE 都更接近用户抱怨的本质。
- 对 UI 的含义：右栏应显示**两个数**——「片基一致性」（base_chroma
  max_abs_drift，物理量）与「有多少帧没有可靠片基」（excluded/
  generic_prior 计数，风险量），并高亮离群帧。

## 3. R5：救援落地 UI + 精确求解（第二轮增补）

### 3.1 精确求解（`neutral_pick_intent_exact` / `neutral_pick_delta_render`）

增量组合 `M(delta)·M(base) ≈ M(base+delta)` 只在当前 intent 仅色温/色调
时成立（LMS 对角乘积可交换）；影调曲线作用于亮度、彩度作用于色度比例，
与色适应**不可交换**。R5a 改为：

```text
输入：技术正片 + 拾点 + base intent（全部控件）
目标：min_{temp,tint}  spread( apply_render(补丁, Intent(temp,tint,固定其余)) )
搜索：粗到细三层网格（21×21 → 9×9 → 7×7 → 7×7），补丁小图渲染 <1s
输出：绝对 temp/tint（吸收 base 已有值），其余控件原样保留
```

测试（`test_rescue.py::TestExactRescue`，5 项）：
- `contrast=25, shadows=-15` 叠加时仍收敛（<25% 残差）；
- base 故意 (-40,-30) 冷/洋红 → 绝对求解一次吸收（残差极差 <0.05）；
- 输入图像逐比特不变（技术契约）；
- 剪裁拾点（B=1.0）警告"信息丢失"；
- 已中性画面保持恒等。

### 3.2 UI 接线（`ui/right_panel.py` + `ui/main_window.py` + `ui/preview_view.py`）

- 右栏「色罩校正」节新增：`中性点救援（点画面里该是灰的地方）`（可勾选）
  + `撤销拾点`（初始禁用）+ `lbl_pick_hint` 一级提示（常驻警告）。
- 勾选 → `view.set_pick_mode("neutral")`（十字光标）；`PreviewView` 的
  neutral 拾点**保持模式**（可连续试多个点），Esc 退出，
  `pick_mode_changed` 同步按钮态。
- 拾点处理（`MainWindow._on_point_picked`）：
  1. 越界/非有限坐标 → 拒绝 + "拾点失败：请点在画面内"（不钳制——
     点到画面外大概率是误点）；
  2. 坐标语义（**2026-09-08 更正**，本节原断言错误）：
     仅当**显示整幅**（输出裁切为空，或勾选「保留片边」）时才有
     VIEW 场景坐标 == oriented small == `_positive_full`（零换算）。
     调整阶段且未勾选保留片边时，`_compose_view` 会把显示图切成整幅正片的
     子矩形（`rendered[y0:y1, x0:x1]`），此时画布坐标必须
     `+ _view_origin` 才是 `_positive_full` 索引——否则用户点画面左上角，
     程序求解的是裁切原点外的像素（v6.1 审计 F5，2026-09-07 真机复现：
     点击场景 (10,10)、裁切原点 (40,20)，实际采样 (10,10) 而非 (50,30)）。
     修复：`_compose_view` 记录 `_view_origin`/`_view_space`，
     `_on_point_picked` 先换算再采样；回归见 `tests/unit/test_v6_2_fixes.py`。
  3. `neutral_pick_intent_exact(_positive_full, y, x, base_intent)` 求解；
  4. 写 `self._intent` + `rec.render_intent_override`（持久化），
     `panel.set_intent(silent)` 同步滑杆，`_compose_view()` 毫秒级生效；
  5. 撤销栈 `self._pick_undo_stack`（换帧清空），「撤销拾点」逐级回退。
- 测试（`test_v6_pick_rescue_ui.py`，10 项）：按钮开关回路、拾点应用 +
  撤销、双拾点双撤销、失衡拾点警告、越界拒绝、技术正片逐比特不变、
  拾点后模式保持。**测试用真实合成负片**（带片基/边缘结构）走全管线，
  拾点坐标程序化选取中亮度低通道比块——纯噪声图的技术正片在深色区
  通道比失衡 10^6 级，会触发正确的警告路径（第一版测试的教训）。

### 3.4 已知边界（如实）

- 拾点只能定对角/二参数适应，不能修染料串扰（需 3x3 矩阵 + 多方向
  样本，可辨识性见 docs/algorithm-notes.md §2.3）；
- 影调/彩度控件下的求解是**当前 intent 固定其余控件**的条件最优；
  用户先动影调再拾点、后大改影调时需重新拾点（提示文案已覆盖）；
- 全套 intent 渲染补丁的求解 <1s/次，网格参数未做速度-精度调优研究；
- Windows 真机验证仍限于阶段 0 窗口（中文标题/按钮/ROI 标签可读，
  `outputs/v6_ui/diag/real_window_stage0.png`）；救援按钮离屏渲染正常
  （无 CJK 字体方框为已知离屏限制，不写成真机已验证）。

## 5. 下一步（按价值排序）

1. **人工判定基准集**（一切"好看"判断的前置，需用户参与 40-60 帧，
   三档判定 + ≥20 帧参考成品）——这是把"救援好不好用""一致性算不算好"
   从数字变成验收的唯一路径。
2. **真机试用取色器**：用户在真实翻车帧上验证"点一下 → 看效果 → 撤销"
   的手感，反馈拾点补丁半径/警告阈值是否合适。
3. 双点（亮/暗中性）联合求解：两个拾点联合约束 (temp,tint) 提升稳健性
   （仍 2 DOF，价值在抗单点误判，不在新自由度）。
4. 片基一致性离群帧联动"以帧为基准重算整卷"（痛点调研 P0-3 的后半环）。
5. 染料串扰 3x3 矩阵研究（Route B bake-off）需要色卡等价物或多色相
   场景统计——排在基准集之后。

# 胶片去色罩：真实用户痛点调研 × 本项目能力差距分析

> 日期：2026-09-05　范围：`/src/film-darkroom` 代码与文档实况 + 外部社区调研
> 目的：回答两个问题——**实际用户在"去色罩/负片转正"时到底卡在哪**，以及
> **我们这个软件真正解决了什么、没解决什么**。
> 结论优先，证据附后（全部为可点开的真实帖子/文档，不含编造）。

---

## 0. 结论摘要（先看这 9 条）

1. **用户的第一痛点不是"颜色不准"，是"同卷不一致 + 自动结果不可预测"。**
   NLP 论坛里"同卷颜色乱飘"是一个长期复发的主题（t8756 / t9738 / t9685 / t6585 /
   t7780 / t6936 / t5683），老手的共识是"别追求绝对准确，要可预期、可复制"
   （t10041、t9744）。我们"卷级起点 + 三候选"的方向是对的，但**至今没有
   任何一个数字证明我们比竞品更一致**（对照方法自己承认无效）。
2. **用户的第二个痛点是"自动失败时怎么低成本救回来"。** 全世界的主流救援动作只有两个：
   **点一个中性点取色** 和 **复制/同步设置到整卷**。
   → **我们没有取色器**（不能点画面里"本该是灰"的地方）。这是最刺眼的功能缺口。
3. **裁切是时间黑洞，也是用户愿意单独掏钱的功能。** 用户为它自己写了
   ottocrop、film-scan-crop、NegPy 的自动裁切，并在论坛喊"这功能我愿意付 8 美元"
   （t9736 / t401 / t10340）。Filmomat €199 的核心卖点之一就是自动框检测+裁切。
   **我们的三 ROI + 自动检测是真实差异化**，但 169 帧样片 `rois_user_confirmed=0`，
   等于"最被看重的功能从没被用户确认过一次"。
4. **除尘是被反复点名的第一大吞吐瓶颈**（t1477 原话："我现在的限速环节是除尘"；
   t10188 / t9802 / t3701 / t866）。我们有 `restoration/dust.py`(300 行)，
   但按 v5 规格被排除在普通路径之外，用户点不到。
5. **"观感层"才是留存关键，而我们明确不做。** NLP 的护城河其实是
   tone profile / Frontier-Noritsu 风格 / 锐化 / Lab Glow-Fade；
   中文社区也一样（"偏一点当日系"）。诚实的判断：**把色罩去正确只是入场券**。
6. **老手对"色罩没除干净"的诊断，最后几乎都指向上游**：背光不均、冲洗偏差、
   过曝/欠曝（薄负片）、单色/夜景场景（t9302、t9738、t10362、t10041）。
   **我们完全没有"采集体检"能力**——这恰恰是成本低、差异化强、竞品也基本没做的点。
7. **市场在 2026 年已经卷成红海，而"脱离 Adobe"这个卖点正在失效**：
   NLP 官方 Standalone（mac/Win/Linux）2026-05 已发预告、Mac beta 先行；
   SmartConvert €199 独立、FilmLab 全平台 $199.99 终身、film Q 浏览器一键 $5/月、
   f8 Develop $49.99（自动从片边测片基 + HDR 输出）、NegPy 免费开源。
8. **本项目目前最大的问题不是算法，是"没有任何一张结果被确认为好看"。**
   验收清单自己写着 `rois_user_confirmed=0`、逐张判定"必须由用户填写，执行 agent 不得代签"、
   对 NLP 的全图 ΔE 对照"不是有效指标"。**6 版规格 + 322 项测试，全都在证明"契约没破"，
   没有一项在证明"颜色好"。** 这就是你不满意的原因，也是必须先补的东西。
9. **最该做的三件事（详见 §6）**：
   ① 建一个"人工判定基准集"（40–60 帧，三档判定 + 你满意的参考成品）；
   ② 补上"中性点取色 + 以某帧为卷基准 + 卷内一致性度量"这条救援与一致性闭环；
   ③ 把自动裁切做成以卷共识的可靠功能并让用户一键接受/纠正。

## 2. 真实用户到底怎么完成"去色罩"

### 2.1 英文社区主流流程（相机翻拍党）

导入 RAW → **在片边（未曝光片基）上点白平衡** → 裁掉/用 Border Buffer 排除非画面 →
NLP 转换（可逐张，也可 Roll Analysis）→ 不满意就调 Temp/Tint 或用取色器点中性灰 →
**Sync/Match 复制到整卷** → 导出 → 单独修少数几张。
（[NLP Getting Started](https://www.negativelabpro.com/guide/basics/)）

### 2.2 中文社区主流流程（翻拍党，几乎全是手工 PS 三板斧）

知乎两篇被反复引用的教程给出了"民间标准做法"：

- **黄昊 Haosky**：RAW → 镜头校正 → **把片基裁干净**（"一定要裁剪干净，否则影响直方图"）→
  R/G/B **三条曲线分别反相并把两端对齐直方图** → 用颜色取样器多点吸"应该是中性灰"的地方 →
  调中间调输出使取样点 RGB 等值 → 得到"无偏色底座"再自由发挥。他强调这是
  **单张计算**，因此"无惧同卷底片因曝光量不同导致的密度不同造成的偏色"。
  （[zhuanlan.zhihu.com/p/24904894](https://zhuanlan.zhihu.com/p/24904894)）
- **砸场子**《彩色负片除色罩经验谈》：色阶法 / 白点黑点灰点法 / **片头片基法**三招，
  并且明确写出各自的失效场景——白点法"不适用于清晨黄昏白炽灯"、
  片头法"对 Ektar 效果很差""对大面积欠曝会把深色区域压死"。
  （[zhuanlan.zhihu.com/p/37682849](https://www.zhihu.com/articles/37682849)、
  补充篇 [p/104371724](https://zhuanlan.zhihu.com/p/104371724)：色阶吸管比曲线算法给阴影更多补偿）
- 豆瓣老帖：相机内白平衡**并不能真正除掉片基颜色**，最后还得进 PS 再平衡一次，
  结果仍不理想；有人靠"把片基曝光到与齿孔同亮"来物理消色罩。
  （[douban group/8814812](https://m.douban.com/group/topic/8814812/)）
- 其它常被引用的实战派做法：西特"仿光放去色罩"、cooltowel 的片基取色法、
  WordPress《彩色底片翻拍-后期调色入门》。

**读出来的三件事**：
① 中文玩家高度依赖手工，**对"自动"的信任度低**，但对手工成本极敏感；
② 他们最在意的两件事是"**别裁错/裁漏**"和"**同卷别飘**"；
③ 中文桌面专业级去色罩工具几乎是空档（手机端一堆低质 App：KLIM、FilmBloom、
负片扫描仪、Posify、时光上色……评分一般但需求真实存在）。

### 2.3 一个正在发生的分裂（重要）

一部分高端用户开始"**用 RGB 三色 sequential 打光把色罩问题物理消掉**"，
然后只做简单反相——原话：
> "转换过程如此基础，以至于不需要 NLP 那种数字'魔法'……我让 Claude 写了个小工具，
> 只做反相，没有任何编辑功能，整卷 35mm 跑一遍就行。"
（NLP 论坛 t10279《Thank you NLP & goodbye》，2026-07；t4012 / t8786 / t5457 同主题）
另有用户主张"窄带 RGB 光源 + 片基对齐直方图 = 根本不需要软件白平衡"（t10041 回帖）。

**含义**：软件去色罩的天花板场景正在被硬件方案侵蚀；但这类用户是极少数，
且**他们的痛点恰好暴露了软件该做的事：不要把自己的"观感"烤死在文件里
（"the look isn't baked in"）、要能整卷批量跑。**

## 3. 痛点图谱（按证据强度排序）

### P1 · 一致性与可预测性（最强烈、最持久）
- t8756（2025-01）：同一卷同一批扫描，**前两张蓝得离谱、后面正常**；同一张单独转换反而正常；
  同一张丢进 FilmLab / SmartConvert 都稳定。
- t9738（2025-09）：同一台机器同一卷 Portra 160，室内 36 张只有 1–2 张有问题，
  **室外"完全不可能一致"**，重扫三遍仍是蓝/洋红/淡黄/中性/高反差乱跳。
- t6585：Roll Analysis 之后"有的帧蓝得没法用 WB 拉回来，只有一帧甚至是纯洋红"。
- t10041（2026-02）：**"Auto-Warm 99% 是一坨橙色灾难；新的 Auto-Mix 比 Auto-Neutral 好，
  但经常在高光引入明显绿偏"**；回帖老手："其它 auto 基本没用，我一直拿 auto-neutral 打底再手调。"
- t9179：Roll Analysis 在**光照条件不同**的同一卷里产生不一致颜色（"曝光差异过大"报错 t7173）。
- t7780 / t6936 / t5683 / t4453 / t9676：相邻两张近似的照片颜色不同、
  "ColorPlus 颜色差且不一致"、"如何获得一致的色彩/统一的视觉风格"。

**根因（社区公认）**：自动白平衡依赖画面里有足够"类中性面 / 色彩与色调多样性"。
**单色主导、夜景、舞台灯、天空占比大、空白帧、薄负片（低对比）**——
这几类画面会让任何统计法乱掉（cameraclara 专文《NLP 色罩问题与修法》把锅归给
"adaptive conversion 在色彩变化不足的图片上失灵"；t9302 回帖实测"低对比 + 色彩种类少"；
t10041 回帖："Portra 偏绿、Ektar 偏红，胶片本身就会偏"）。

### P2 · 失败时的救援成本
- 用户愿意学的动作很少且固定：**点中性点 / 调两滑块 / 复制设置**（NLP 文档、RT 手册、Filmomat 都是这套）。
- 但 NLP 的取色器在 Windows 上要**关掉图形处理、按住 3 秒才采样一次**
  （[官方指南原文](https://www.negativelabpro.com/guide/basics/)）——**体验差到有名字**。
- 老手抱怨"一张张手动调，我没时间"（t9302 原话："我总不能一张张修，我真的没时间"）。
- t10155《你会把所有校正都放在 NLP 里做吗》、t5584（局部调整该在负片还是正片副本上做）：
  **"在哪一步做、能不能撤销"本身就是困惑源。**

### P3 · 裁切与几何（被低估的大痛点）
- t401（2019 起，18 回复）：能不能自动裁掉扫描边框；作者自己写 OpenCV 原型，
  官方承认"以后可能加"。
- t9736（2025-09）：**"手动裁切太枯燥了，NLP 明明在分析阶段已经自动裁过了，
  为什么把这个信息扔掉、让用户再做一遍？"** → 作者两小时后写了脚本，
  并说"这功能该值 8 美元"；随后 2026-08 有人做了 web 工具
  **ottocrop**（t10340：明确说"**用卷级共识**做检测，因为整卷遮罩几何恒定"，
  并且指出**齿孔/片边不在反相前去掉会严重污染颜色**、
  用户要求"处理 RAW 并输出 sidecar XMP 让反相软件沿用裁切"）。
- t9885《Auto rotate request》、t3929（半格相机中缝）、t6373/t10189（120/多帧切分）、
  t1343（整条 vs 单帧转换结果不同）、t470（想保留片边）、t875/t8472（导出加边框/片边发白）。
- Filmomat 用户："**自动裁切不总是好用，可惜**"（t10355）——说明这功能连卖 €199 的都没做稳。

### P4 · 除尘与脏点（吞吐第一瓶颈）
- t1477：**"我现在流程的限速环节就是除尘"**；t10188（自动除尘脚本需求）；
  t9802（LR 15 的新除尘功能对底片没用）；t3701《想要一条真正的 iSRD 管线》(20 回复)；
  t866（SilverFast 48bit RAW 下 iSRD 被禁用，除不了尘）；t3714（同位置反复出现的白点）；
  t8377（未裁切长条更容易沾灰）。
- 中文侧同样存在（翻拍党靠气吹+静电刷+粘尘辊，"抽拉底片压平"是常见工程话题）。

### P5 · 影调与动态范围（"灰、闷、死白、死黑、噪"）
- t9917《Color Clipping Issues》(20)、t1308（日落高光恢复）、t5530（批量转换"发虚/薄"）、
  t7235（薄负片噪点远大于电分）、t9908（欠曝区域起雾，23 回复）、
  t8875（高光爆掉）、t9899（阴影强绿/蓝偏）。
- 常见建议非常一致：**别过度 ETTR**、高光掐一点、"薄负片别指望软件变出信息"。
- 中文教程同理：色阶掐头尾会**加大反差压暗**，需要 shadow/highlight 找回。

### P6 · 输入格式与色彩管理（"我以为它是线性的"）
- TIFF gamma 1.0 / 1.8 / 2.2 之争（NLP 专门做了 TIF Scan Prep 工具，t2162）；
  VueScan / SilverFast 的 RAW DNG 必须先跑一次 profile 更新，否则 NLP 不认（t1162、t23）；
  **"TIF 绝对不要在 LR 里点白平衡，会制造色偏"**（官方指南原文，NLP 特意写警告）；
  Silverfast HDR RAW 与 iSRD/位深互斥（t866/t953）；
  换电脑/换系统后"重新计算导致整体过曝色偏"（t4617、t8897）。
- 结论：**编码识别、ICC、位深、来源判定是真实事故源，也是我们能建立信任的地方。**

### P7 · 性能、稳定性、平台依赖
- 速度：t9803（LR15 之后一卷 36 张从 5 分钟变 20 分钟）、t7361（打开慢）、
  t7793（拖滑杆要等几秒）、t7142（**一天几千张，想全自动，NLP 批量顶不住**）、
  t8924（导出速度实测：别勾"加入目录"）、t10244（**批量超过某个数量元数据写入失败**：
  1/5/10 张可以，20+ 失败）。
- 崩溃：t9526/t9833（Roll Analysis 直接崩）、t10155、t7259（写元数据报错，19 回复）。
- 平台：t10022（**"我的电脑装不了新版 LR，请出独立版"**，33 回复；官方 2026-02 承诺
  mac/Win/Linux 原生二进制，5 月发预告，Mac beta 先行）；t7198/t295/t5647（要 Capture One /
  Affinity / Luminar 版）；t8187（**"如果真做独立版，请带上命令行"**）；t10268（"独立版：
  对手没在睡觉"）。
- 迁移/授权：t10279（老用户转投 RGB 打光，"几千张"）、t8858（众筹请求）、t8009/t9710（预设丢了）。

### P8 · 风格、观感、颗粒、锐化、halation（留存层）
- NLP 的 tone profile（Cinematic / Lab / Linear × 变体）、LUT（Natural / Frontier / Crystal / Pakon）、
  Lab Glow/Fade、Sharpen: Lab/Scanner、pre-saturation —— **这是用户真正拿来发作品的东西**。
- 高频具体抱怨：**红色过饱和**（t8275）、"树叶太绿红太艳"（t9328）、"和 Noritsu 电分比偏红"（t6292）、
  "电分为什么比自家好看"（t7006/t1338）、肤色阴影偏红（t5692/t8445/t2352）、
  "怎么获得原味胶片感"（t3862）、颗粒抑制（t5979/t9877）。
- halation 几乎是空白（全论坛只 2 帖）。

### P9 特别项 · 过期卷 / ECN-2 / 交差冲洗（cross-process）/ 老档案
- 中文侧这是**巨大且高热的话题**：知乎多篇长文讲过期卷偏色机理
  （感红层先衰→偏青蓝；感绿层衰→偏绿；**成色剂不稳导致品红最容易失控**；
  灰雾升高让"纠偏变得极其困难"；建议宁过勿欠、+1~+2 档）
  （[question/22533511](https://www.zhihu.com/question/22533511/answer/2012113216017299296)、
  [question/356315073](https://www.zhihu.com/question/356315073/answer/2072433639925851889)）。
  结论性态度很有意思：**"我通常只校到'看着舒服'，不是'数据准确'"**——
  与英文社区 t10041 老手"我根本不在乎 WB 准不准，只要能得到我要的图"**完全一致**。
- 老 Fuji/老卷"不可救药"（t10073、t9302、t8729 老化褪色）；
  ECN-2/电影卷要送洗、色罩不同（t1795）；交差冲洗偏色"后期不可能校正"（知乎 641806126）。
- film Q（2026-06 上线）已经把**"褪色正片的色偏"与"过期卷灰雾"**当作差异化卖点——
  说明这个细分需求已经被商业对手盯上。

## 4. 2026 年竞品格局（价格与能力，2026-07 数据）

| 产品 | 平台 | 价格 | 关键能力 | 用户吐槽点 |

## 5. 本项目实况（代码/文档核对后的事实）

### 5.1 已经存在、且有代码支撑的能力
- 统一管线：`pipeline/service.py`（586）· 密度反相 `density.py`（286，逐通道幂指数 + 软趾 + 高光膝 + sRGB 编码 + 分块）
- 卷级片基：`roll_analysis.py`（433）多取样区密度域稳健估计（q75 中心 + decade 容差）、
  卷级汇总、缺片基帧继承卷级、全卷失败回退**版本化通用先验**（明确"非物理测量"）
- 自动色彩起点：`candidates.py`（444）SoG p=1/2/6 + 白点 + Gray-Edge **多估计器方向/幅度一致性**
  → 置信度；对高饱和/单色/夜景/剪裁/**中性像素占比过低**分别惩罚，
  置信度低时整卷回退"保留氛围"；卷级起点用中位数 + 偏离 35% 剔群（防单张污染整卷）
- 三候选（保留氛围/中性/偏暖）共享同一技术正片；微调 `render.py`（396，
  Bradford 色适应 + 受保护支点曲线 + 单调影调 + 自然饱和度），默认恒等不改技术正片
- 三 ROI（输出裁切/有效画面/多个片基取样区）+ 归一化相对坐标 + 整卷同步 + 细微旋转 + 镜像
- 输入归一化：`color/management.py`（356，TIFF 分类 / DNG 分类 / ICC / 编码枚举），
  采集指纹（EXIF+解码策略），**不静默猜编码**
- 事务式整卷导出 + sidecar v4（含 provenance/诊断/git commit）+ CLI（import/invert/batch/roll/profile）
- v6 单工作区 UI（Lightroom 式，深色 QSS，分析/调整两阶段，即时合成，直方图）
- **除尘代码存在但被藏起来了**：`restoration/dust.py`（300，检测 +  inpaint + 沿条纹传播）+ 测试，
  普通路径不暴露（grep 显示 `halation/sharpen/stitch/straighten/preset` 全为 0 命中）
- 规模：src 14,236 行；tests 4,974 行 / 30 文件（自述 322 passed）

### 5.2 项目自己承认的缺口（原文）
- `docs/remediation-progress.md`：P0-8 **逐卷视觉门禁 = 等待用户签字**；
  169 帧 5 卷、`parity_required=132`、`robustness_only=37`、**`rois_user_confirmed=0`**；
  视觉抽查结论"与 NLP 相比存在轻微色偏——逐张结论必须由用户填写，执行 agent 不得代签"。
- `docs/support-matrix.md`：真实**扫描仪 TIFF 0 张**、DNG 0 张、**设备覆盖 1 台（NIKON）**、
  光源覆盖全部 unknown → "跨设备泛化一律未验证"；CN400 无 NLP 对照。
- `docs/nlp-comparison.md`：**"全图 ΔE2000 对 NLP 不是有效的色彩验收指标"**
  （裁切不同/旋转拟合乱跳/风格曲线不同），因此"我们 vs NLP"实际上**没有可比结论**。
- `docs/blockers.md`：Z8 高效 NEF（AV1）无法解码 → ECN-2 证据其实是
  **Lightroom 导出的 16bit TIFF（sRGB 显示编码线性化）**，不是原生线性数据。

### 5.3 近 12 次提交在做什么（git log）
全部是 UI 交互/响应性/主题/即时合成/高清预览/竞品对齐——**算法主线停在 v5 P0，
没有一次提交在推进"真实样片视觉验收"或"跨设备证据"。**

## 7. 三个"我们其实没解决"的核心判断

1. **我们没有解决"信任"。** 用户判断一个去色罩工具，只看两件事：
   "这一卷看起来是不是同一卷"和"翻车时我 5 秒能不能救回来"。
   我们现在**既没有前者的一致性证据，也没有后者的取色救援**。
2. **我们没有解决"被验证"。** 169 帧 `rois_user_confirmed=0`、视觉门禁"等待用户签字"、
   对 NLP 的对照"不是有效指标"。这意味着 v5/v6 的 322 项测试
   证明的是"数据契约不破"，**不是"图变好看了"**。项目自评体系里
   缺一个"人眼判定 + 参考成品"的基准集——这是**唯一能让后续改进有意义的前置条件**。
3. **我们没有解决"用户愿意付钱的那部分体验"**：自动裁切敢用、除尘敢用、
   批量快、导出快、观感好。我们解决的是"工程上正确"的那部分。

同时提醒三个反向风险（避免下一版又跑偏）：
- 别把"三候选"当卖点吹。它是好设计（对夜景/单色场景正确），但**用户语言是"这一张我想要中性一点"**，
  不是"三个候选"。
- 别继续扩规格。v1→v6.1 的教训是：**规格越写越厚，真实样片验收一步没走。**
- 别追"绝对色准"叙事（v2 调研里已经被否掉：没有真值时不能宣称绝对还原），
  社区态度也是"看着舒服 > 数据准确"。

## 8. 建议优先级（可直接执行，每条都有验收口径）

### P0（2–3 周，直接改变口碑）
1. **人工判定基准集（一切改进的前置）**
   从 169 帧里挑 40–60 帧（必须含：夜景/舞台、天空占比大、单色主导、老卷/过期、
   薄负片、逆光、含片基与不含片基各若干），你逐张打三档
   （① 可直接发 ② 微调可救 ③ 不可用）+ 对其中 20 帧给出"你满意的参考成品"
   （你自己调的或电分/NLP 出的）。
   **验收口径**：自动结果 ≥70% 落①、≥95% 不落③；② 中 ≥80% 在 1–2 步内救回。
   这就是可复现的回归集，也是"我们比 NLP 好还是差"的**唯一有效对照**。
2. **中性点取色救援**（单点为主，双点（亮/暗中性）作进阶）
   点完立刻出结果、可撤销、可"仅同步色温色调到整卷"、可一键回候选。
   **验收口径**：在基准集"② 微调可救"子集上，救回率 ≥80%，且平均操作 ≤2 次点击。
3. **"以帧为基准"的卷一致性 + 卷内一致性度量**
   右栏显示本卷各色温/色调/中位密度散布（一条小折线即可），
   允许"以当前帧为卷基准重算全卷"，并高亮离群帧。
   **验收口径**：t9738/t8756 类场景（同卷明暗差异大）人工判"一致"比例 ≥ 你手头的 NLP 结果。
4. **自动裁切做到"敢用"**：引入**卷级共识**（同一卷遮罩几何恒定）提升检出稳定性，
   加"接受/重画/整卷沿用"三步闭环；导出把裁切写进 sidecar 且可被外部沿用。
   **验收口径**：基准集上自动检出的**人工返工率 ≤10%**（Filmomat 现在做不到）。

### P1（1–2 月，决定能不能给别人用）
5. **借/借调一台扫描仪造真实样片**（Epson V600/V850 或 Plustek，30–50 帧即可）：
   解锁"扫描仪 TIFF/DNG/第二设备"三格 `missing-fixture`——**这是"跨设备泛化"从 0 到 1**。
6. **采集体检报告**（背光均匀性、逐帧曝光漂移、暗部/高光剪裁、薄负片、单色场景预警、
   片基漂移），全部用**人话中文**（不出现 Dmin/Dmax/矩阵/指数）。
   这一条能把社区里 90% 的"你这软件偏色"从软件身上摘掉，**是最便宜的差异化**。
7. **除尘接入普通路径**（先只做：检测 → 生成选区 → 一键修补 → 可撤销；
   再考虑原图配准/红外通道）。**验收口径**：整卷人工修尘时间下降 ≥50%。
8. **吞吐基准**：整卷 36 帧（Z8 8256×5520）冷启动→可导出的秒数、内存峰值、
   1000 帧批量成功率，写进 docs 并与"SmartConvert 6 张几秒 / NLP 一卷 5–20 分钟"对标。

### P2（观感与差异化，需要审美投入）
9. 高光/阴影恢复策略、锐化档（Lab 软锐 / 保留颗粒）、颗粒一致性、
   Frontier/Noritsu 风格档（**先做 2 个，不做 10 个**）、halation（社区空白）。
10. 过期卷/灰雾档（对标 film Q）、黑白负片（简单反相即可）、反转片（不反相）另立流程。

## 9. 一句话定位建议（给下一版规格）

> **"导入一整卷，不用色卡、不用 Adobe，同卷结果稳定得像同一次冲洗；
> 翻车时点一下灰就行，而且它告诉你哪里是设备的问题。"**

四个可证明的支点：卷内一致性（有数字）、1–2 步救援（有取色器）、自动裁切返工率（有统计）、
采集体检（竞品没有）。**"无需色卡/离线/无订阅"降级为背景条件，不再当主卖点。**
